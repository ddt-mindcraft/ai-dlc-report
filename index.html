Inception 산출물 검토

Inception의 요구사항·스토리·실행 계획·애플리케이션 설계·작업 단위 문서 검토를 마쳤습니다. Construction과 제품 구현은 시작하지 않았습니다.

아래 링크는 실제 AI-DLC 산출물의 고정된 버전입니다. 문서 검토·승인과 제품 실행 검증은 별개입니다. 이 요약은 팀 검토용이며 제품 입력 파일에 포함되지 않습니다.

핵심 결정

  • 비개발자와 AI 에이전트 지식이 적은 사용자를 위한 Windows CLI/TUI 제품. Pi 기반, Worker(저비용)/Planner(고성능), 단일 EXE를 목표로 합니다.
  • Airouter는 테스트·데모용이며 실제 사용자는 셋업 과정에서 자신의 프로바이더·모델·인증을 설정합니다.
  • 제품 전체는 하나의 작업 단위이고 14개 컴포넌트를 7개 논리 모듈 그룹으로 구성합니다. 내부 격리 자식 프로세스도 같은 제품에 속합니다.
  • 권한은 작업마다 새로 확인합니다. 재개는 같은 Episode의 새 Run으로 기록하며 결과 불확실 동작을 자동 반복하지 않습니다.
  • 검색은 기본 60초의 변경 가능한 타임아웃만 둡니다. 100/100/20GiB는 용량 검증 목표이며 저장 한도가 아닙니다.
  • 별도 NFR 단계는 생략하되 확정 NFR·기능 수용 기준·PBT·검증 게이트는 후속 설계와 검증으로 전달합니다.
  • 동일 단계에서 문제 검출이 2회 반복되면 Astra가 작성·검토·조율 과정까지 직접 재검토하는 방침을 적용했습니다. 이는 리뷰용 운영 설명이며 제품 사양에는 포함하지 않습니다.

1. 목적·사용자·제품 형태

MindCraft는 비개발자와 AI 에이전트 지식이 부족한 사람도 자연어로 코드·문서를 분석하고 정리·생성·가공하며, 이전 결과를 다음 작업에 쉽게 재사용할 수 있게 하는 개인용 도구다. 개발자도 사용할 수 있지만 전문 용어·명령어·에이전트 구조를 알아야 시작할 수 있는 제품으로 만들지 않는다.

Windows CLI/TUI만 목표로 한다. Pi를 기반으로 구축하며 일반 사용자는 셋업을 통해 자신이 실제로 사용할 모델과 연결 서비스를 설정한다. Airouter는 테스트·데모용 연결로 사용한다. 배포물은 실행에 필요한 기반을 포함한 EXE 한 파일이다. 별도 Node.js·npm·Pi 설치를 사용자에게 요구하지 않는다.

첫 화면에서 원하는 작업을 자연어로 적고 안내에 따라 시작할 수 있어야 한다. 현재 무엇을 하는지, 어떤 자료를 읽는지, 무엇을 허용하는지, 다음에 무엇을 누르면 되는지 쉬운 한국어로 설명한다.

성공 결과는 초보자가 프로그램 실행→연결 설정→요청 입력→결과 확인→이전 작업 이어하기를 수행하는 것이다. 세부 모델·도구·실행 ID는 필요할 때 펼쳐 확인하게 하고 일상 화면에서 필수 지식으로 요구하지 않는다.

2. 용어와 책임 경계

  • Workspace(작업 폴더): 지정은 선택 사항이다. 지정하지 않으면 사용자가 실행한 EXE가 놓인 폴더를 사용한다. 셸의 현재 폴더나 임시 압축 해제 위치를 기본 작업 폴더로 오인하지 않는다. 현재 폴더를 쉬운 표시로 알려주며 변경할 수 있다.
  • Task: 사용자가 달성하려는 작업 목적. 이름과 고유 ID를 가지며 여러 Episode를 포함한다.
  • Episode: Task 안에서 한 번의 사용자 요청을 처리하는 논리적 작업 단위.
  • Run: Episode를 수행한 개별 실행 시도. 실행 상태·선택 모델·결과·오류·재개 관계를 가진다.
  • Session: 프로그램을 시작해 종료할 때까지의 사용 구간. 여러 Session이 같은 Workspace의 기록을 순차적으로 이어갈 수 있다.
  • Knowledge: 작업 결과와 출처 정보를 함께 보존한 재사용 자료. 후보·사용 가능·거부 상태를 구분한다.
  • 모델: 사용자가 셋업에서 실제 사용할 모델과 연결 정보를 지정한다. Worker는 저비용 처리용, Planner는 고성능 계획·분석용이다. 모델 1개는 두 용도에 공용으로 사용할 수 있다. Pi는 제품의 필수 실행 기반이며 사용자가 내부 기반을 설치하거나 이해할 필요 없이 사용할 수 있어야 한다.
  • 제품의 승인 요청은 파일 변경·명령 실행 등 사용자의 실제 작업 권한을 묻는 런타임 기능이다. 작업 요청 내용 자체를 해당 권한의 포괄 승인으로 간주하지 않는다.

3. 주요 사용자 여정

  • J-01 첫 실행: EXE 실행 → 현재 기본 작업 폴더 확인(변경은 선택) → 사용할 연결 서비스와 모델 설정 → 필요한 인증 정보 입력 → 연결 확인 → Worker/Planner 용도 배정 → 자연어로 첫 작업 입력 → 진행·결과 확인. 테스트·데모는 별도로 표시하고, 일반 사용에 Airouter를 필수로 요구하지 않는다.
  • J-02 코드·문서 분석: Task 선택 → 허용된 자료와 Knowledge 검색 → 투입할 맥락 미리보기 → 지정 모델로 분석 → 출처와 결과 확인 → 재사용할 결과를 Knowledge로 선택.
  • J-03 문서 생성·가공: 원문과 목표 지정 → 결과 초안 확인 → 파일 변경 대상과 내용 승인 → 저장 → 실제 저장 결과와 실행 이력 확인. 거부 시 파일은 바뀌지 않는다.
  • J-04 중단 후 재개: 실행 중 취소 또는 종료 → 다시 실행 → 이전 작업 이어하기 선택 → 확인이 필요한 동작 안내 → 같은 Episode에서 새 Run으로 재개. 이미 수행됐을 수 있는 외부 동작을 무조건 반복하지 않는다.
  • J-05 재사용: 이전 결과 후보 목록 → 내용·출처 확인 → 사용 가능으로 승격 → 후속 요청에서 관련 자료 선택 → 포함·제외 사유 확인 → 결과 생성.

F-01. 작업 공간 선택·진단

  • 동작: 작업 폴더 지정은 선택이다. 미지정 시 실행한 EXE의 디렉터리를 기본으로 표시한다. 작업 폴더·일반 설정·보호된 자격증명 저장 위치는 구분한다.
  • 진단: 실행 환경, 기록 저장 가능 여부, 저장된 모델 설정, 선택한 연결 서비스의 준비 상태를 각각 보여준다. 첫 실행이나 설정 누락 시 종료하는 대신 단계별 셋업을 연다. 설정 메뉴에서 나중에 수정할 수 있다.
  • 실패: 기본 폴더에 기록할 수 없으면 이유와 다른 폴더 선택을 안내한다. 사용자가 모르게 다른 폴더로 바꾸지 않는다.
  • AC-01: 임의의 셸 폴더에서 EXE를 실행해도 작업 폴더를 지정하지 않았다면 EXE 위치가 선택된다. 모델 미설정 상태에서도 안내를 읽고 셋업을 완료할 수 있다. 선택 모델의 연결 확인이 실패하면 이유·수정 방법을 보여주며 다른 모델로 조용히 실행하지 않는다.

F-02. Task 생성·목록·선택·상태

  • 동작: Task 이름을 입력해 생성하고, 저장된 Task 목록을 조회하며, 현재 Task를 선택한다. 완료·취소된 작업도 이력으로 확인한다.
  • 실패: 빈 이름·존재하지 않는 ID는 명확한 오류로 처리한다. Task 선택 없이 실행을 요청하면 생성·선택을 안내한다.
  • AC-02: Task 두 개를 생성하고 서로 전환했을 때 각 작업의 실행 목록과 결과가 섞이지 않는다. 프로그램을 다시 실행해도 ID와 선택 가능한 목록이 보존된다.

F-03. Episode·Run 실행과 진행 표시

  • 동작: 선택한 Task에 요청을 입력하면 Episode와 Run을 구별해 기록한다. 실행 중 응답 스트림·도구 요청·도구 결과·오류·현재 상태를 보여준다.
  • 실패: 모델 시작 실패·호출 실패·응답 완료를 구별하고, 실행 시작을 성공 완료로 표시하지 않는다. 빠른 연속 입력은 순서가 보장되거나 실행 대기임을 명시한다.
  • AC-03: 실행 전후 같은 Run ID로 요청·선택 모델·시작·완료 또는 실패를 조회할 수 있다. 실행 중에도 상태 확인과 취소 입력을 처리할 수 있다.

F-04. 명시적인 모델·용도 선택

  • 동작: 모델 0개이면 실행을 차단하고 설정을 안내한다. 1개이면 모든 용도에 사용한다. 2개이면 Worker(저비용)와 Planner(고성능)에 각각 하나씩 배정한다. 같은 용도의 복수 배정이나 2개 초과 구성은 설정 오류로 안내한다.
  • 사용자는 쉬운 용도 설명을 보고 자신이 사용할 모델을 지정한다. 실행 전에 선택 모델·용도·연결 서비스와 준비 상태를 표시한다. 비용 정보가 없으면 추정값을 사실처럼 표시하지 않고 미확인으로 알린다.
  • 실패: 지정한 모델을 쓸 수 없으면 사용자 조치를 안내한다. 다른 모델을 자동 추가·대체하거나 실행 도중 조용히 전환하지 않는다.
  • AC-04: 모델 1개로 두 용도를 수행할 수 있고, 2개일 때 각각 지정한 모델을 사용한다. 잘못된 설정은 호출 전에 차단된다. 지정 모델 실패 시 임의 대체 호출이 없다.

F-05. 사용 모델 셋업·테스트와 데모 연결

  • 동작: 일반 사용자는 셋업에서 지원하는 연결 서비스·방식과 모델을 선택하거나 직접 입력한다. 필요한 서비스 주소와 인증 정보는 연결 방식에 따라 안내한다. 지원 여부·필수 항목·입력 예시를 보여주고, 지원하지 않는 연결을 설정 성공으로 표시하지 않는다.
  • 셋업 순서: 사용할 서비스·모델 지정 → 필요한 연결·인증 정보 입력 → 연결 확인 → Worker/Planner 배정 확인 → 설정 저장. 연결 서비스와 모델의 차이를 쉬운 말로 설명한다. 기술 설정 파일을 직접 편집할 필요가 없어야 한다.
  • 저장한 모델 설정은 다시 실행해도 유지되며 설정 화면에서 확인·수정할 수 있다. 자격증명은 일반 설정과 분리해 보호한다. 연결 확인 실패 시 수정·다시 확인·나중에 설정을 안내하고, 미완성 설정으로 실제 작업을 시작하지 않는다.
  • 테스트·데모: Airouter를 테스트 및 데모용으로 사용하며 해당 용도를 화면과 실행 이력에 표시한다. 일반 사용에 Airouter 계정·연결을 강제하지 않는다. 데모 설정을 일반 사용 설정으로 자동 복사하거나 지정 모델 실패 시 Airouter로 자동 대체하지 않는다.
  • 오프라인 검증: 자격증명과 모델 네트워크 호출 없이 반복하는 샘플은 Airouter 테스트·데모 및 일반 사용 모델 실행과 별도로 구분한다. 오프라인 성공을 실제 연결 성공으로 표시하지 않는다.
  • AC-05: 처음 실행한 비개발자가 안내만으로 실제 사용할 모델의 연결과 Worker/Planner 배정을 설정할 수 있다. 설정 저장 후 재시작해 같은 연결 정보를 사용할 수 있다. 실제 Run은 지정한 모델·연결을 사용하고 테스트·데모 설정으로 임의 전환하지 않는다.

F-06. 사용자 작업 권한과 승인

  • 동작: 작업 폴더 안에서 자료를 검색·읽을 수 있다. 외부 폴더 접근은 해당 접근마다 경로·목적·할 일을 보여주고 사용자 권한을 요청한다. 승인 권한을 저장해 다음 접근에 재사용하지 않는다.
  • 파일 쓰기·삭제·명령·네트워크처럼 상태를 바꾸는 작업은 대상·변경 내용·필요 권한을 설명하고 승인 또는 거부를 받는다. 사용자가 전문 명령어를 읽어야만 의미를 파악할 수 있는 안내는 피한다.
  • 경로를 실제 대상으로 해석했을 때 외부 폴더이면 외부 접근으로 처리한다. 권한은 해당 요청의 대상·내용에만 적용하며 모델이 자신에게 권한을 줄 수 없다.
  • AC-06: 같은 외부 폴더를 두 번 접근하면 두 번 권한을 요청한다. 첫 승인으로 두 번째 접근이나 변경된 대상을 허용하지 않는다. 거부 시 접근하지 않고 이유를 표시한다. 승인 기록 저장 실패 시 동작을 시작하지 않는다.

F-07. 파일·명령 실행 결과 확인

  • 동작: 승인한 파일 변경·명령을 요청 범위에서 실행하고 실제 결과를 확인한다. 별도 작업 수·명령 종류·메모리 상한을 추가하지 않으며 사용자 권한 경계는 지킨다.
  • 결과 확인 필요: 파일 저장 직후 프로그램이 꺼지는 등 실제 작업은 됐을 수 있지만 완료 기록이 없는 상태다. 화면에는 “이 작업이 완료됐는지 아직 확인하지 못했어요”처럼 표시한다. 성공 또는 실패로 단정하지 않는다.
  • 설계 대안: 프로그램이 권한 범위 안에서 파일 내용 등 확인 가능한 사실을 먼저 조사한다. 확인할 수 없다면 작업명·대상·이미 실행됐을 가능성을 설명하고 “직접 확인한 뒤 다시 실행 / 이번에는 건너뛰기 / 나중에 결정”을 제공할 수 있다. 결과 확인 화면의 구체적인 선택지는 미정이다.
  • AC-07: 결과가 확인되지 않은 작업을 재개 시 자동 반복하지 않는다. 확인된 사실과 추정을 구분하고 사용자에게 재실행 여부를 알 수 있는 쉬운 안내를 제공한다.

F-08. 영속 이력·순차 세션

  • 동작: Task·Episode·Run·Session·모델·권한 결정·도구 결과를 관계가 유지되게 저장한다. 재시작해 이전 기록을 이어간다. 동일 작업 폴더에서 동시 다중 실행은 지원하지 않으며 살아 있는 기록자의 잠금을 해제하지 않는다.
  • 실패: 저장 실패를 사용자에게 알리며 저장되지 않은 결과를 저장 완료로 표시하지 않는다. 기존 실행자가 살아 있으면 두 번째 기록자를 차단한다.
  • AC-08: 종료·재시작 후 기존 작업·실행 결과를 확인할 수 있다. 손상 기록은 정상으로 읽지 않고 원본을 보존하며 쉬운 오류를 안내한다. 보존기간 설정·삭제·내보내기·수동 복구용 별도 화면은 제공하지 않는다.

F-09. 취소·종료·재개

  • 동작: 실행 취소 시 중단 상태와 당시 결과를 보존한다. 정상 종료 시 정리 결과를 남기고, 비정상 종료 후 재시작하면 미완료 Run을 식별한다.
  • 재개는 같은 Episode를 유지하고 새 Run을 만든다. 기존 Run을 덮어쓰지 않으며 원본·재개 시도 관계를 남긴다. 사용자 화면에서는 “이전 작업 이어하기”로 설명한다.
  • AC-09: 취소된 실행은 성공으로 보이지 않는다. 강제 종료 뒤 이전 실행·불확실 동작을 확인할 수 있고, 재개 후 원본 및 새 Run을 모두 조회할 수 있다.

F-10. Knowledge 후보·상태 관리

  • 동작: 결과 본문과 생성 Task/Run·시각·출처·자료 종류를 Knowledge 후보로 저장한다. 사용자는 목록·검색·상세에서 내용과 출처를 확인하고 승격 또는 거부한다.
  • 실패: 출처 없는 결과를 출처 검증 완료로 표시하지 않는다. 자격증명·민감정보는 재사용 자료와 화면·오류에 노출되지 않도록 처리한다.
  • AC-10: 생성 직후 후보는 다음 요청의 사용 가능한 맥락에 자동 포함되지 않는다. 승격 후에만 사용할 수 있고 거부한 자료는 제외된다. 원본 Run과의 관계를 확인할 수 있다.

F-11. 관련 자료 검색과 맥락 구성

  • 동작: 관련 Knowledge와 작업 폴더 자료를 자동 검색한다. 자료가 부족하면 검색 범위를 넓히고, 외부 폴더를 읽어야 하면 매번 권한을 요청한다.
  • 검색에 별도 파일 수·파일 크기·검색 자료 총량·확장자·폴더 종류 제한을 두지 않는다. 검색 범위와 관련성 판단, 민감정보 노출 방지, 외부 폴더 권한은 자료를 다루는 기본 동작으로 유지한다.
  • 검색 시간 제한은 변경 가능해야 한다. 초기값 후보는 60초다. 만료 시 지금까지 찾은 결과와 미완료 상태를 보여주고 추가 검색을 선택할 수 있게 한다. 검색 제한 시간을 모델 작업 전체의 시간 제한으로 확대하지 않는다.
  • 모델에는 요청과 관련된 내용을 구성해 전달한다. 제공자의 실제 입력 길이 한계가 있으면 분할 처리하거나 사용자에게 이유를 설명하며 검색 자체를 임의 파일 수·크기 상한으로 줄이지 않는다.
  • AC-11: 파일 수나 개별 크기만으로 검색 대상을 사전에 배제하지 않는다. 시간 만료를 “검색 결과 없음”으로 표시하지 않는다. 승인되지 않은 외부 폴더는 읽지 않으며 후보·거부 Knowledge를 사용 가능 자료로 자동 승격하지 않는다.

F-12. 맥락 미리보기와 투입 내역

  • 동작: 실행 전에 포함할 자료·버전 또는 내용 식별값·순서·길이·제외 사유를 미리 보여준다. 실제 실행 직전 확정된 투입 내역을 Run에 남긴다.
  • 실패: 미리보기 이후 자료가 바뀌었다면 실제로 사용한 내용을 기준으로 다시 계산하고 변경·차이를 알 수 있게 한다.
  • AC-12: 사용자는 결과가 어떤 자료를 이용했는지 추적할 수 있다. 미리보기와 실제 투입 내역이 다르면 이전 미리보기를 실제 사용 기록으로 표시하지 않는다.

F-13. 설정·자격증명 관리

  • 동작: 모델·서비스 주소·용도·작업 폴더 등 일반 설정과 자격증명을 구분한다. 자격증명은 보호된 저장 방식으로 제공한다. 운영체제의 보호 저장 기능 또는 실행 환경을 사용할 수 있으며 구체적인 방식은 설계에서 정한다.
  • 실패: 자격증명 저장소를 사용할 수 없으면 이유를 안내하며 평문 설정으로 조용히 대체하지 않는다.
  • AC-13: 설정 파일·명령행 인자·오류·이력·Knowledge·배포 파일에 실제 자격증명이 남지 않는다. 진단 결과는 자격증명 값 없이 준비 여부를 보여준다.
  • 셋업 화면은 인증값을 가리고 값 자체를 진단 결과·일반 설정·실행 이력에 표시하지 않는다. 설정 변경 시 저장된 연결 정보와 인증 준비 상태를 구분해 안내한다.

F-14. 단일 EXE 배포·실행

  • 동작: 사용자가 받는 실행 배포물은 EXE 한 파일이다. Pi와 필요한 실행 기반을 포함하며 Node.js·npm·별도 Pi 설치나 옆에 둔 필수 런타임 폴더를 요구하지 않는다. npm 배포나 별도 설치형을 필수 납품으로 만들지 않는다.
  • 실행 후 사용자의 작업 결과·설정·이력 데이터는 별도 파일로 생길 수 있다. 내부 런타임 임시 전개가 필요해도 사용자가 준비하는 파일은 EXE 하나이며, 기본 작업 폴더는 원래 EXE 위치로 유지한다.
  • AC-14: 별도 개발 도구가 없는 Windows 환경에서 EXE 하나를 옮겨 실행하고 첫 설정·작업 수행이 가능하다. 한글·공백이 있는 경로를 처리한다. 기존 사용자 데이터와 작업 파일을 실행·교체 과정에서 임의 삭제하지 않는다.

F-15. 비개발자 친화적인 Windows CLI/TUI

  • 동작: 자연어 요청, 선택 목록과 예시, 단계별 첫 실행 안내를 제공한다. Task/Episode/Run/Provider 대신 “작업/요청/실행 시도/연결 서비스”를 우선 표시하고 내부 명칭은 상세 정보로 제공한다.
  • Worker는 “일반 작업 · 저비용”, Planner는 “계획·복잡한 분석 · 고성능”처럼 설명한다. 오류·권한 요청에는 무엇을 하려는지, 영향, 다음 행동을 함께 보여준다.
  • 진행 중에도 입력·상태 확인·취소·도움말 접근이 가능하게 한다. 빈 목록·실행 대기·오류·완료를 구분하고 성공을 모호한 기술 로그로만 알리지 않는다.
  • AC-15: AI 에이전트 용어·명령어 사전 지식 없이 화면 안내만으로 첫 연결 설정→자료 요약→결과 확인→이전 작업 이어하기를 수행할 수 있다. Windows에서 한글 입력·연속 입력·창 크기 변경·스크롤·취소·종료를 실제 확인한다. 별도 반응 시간 상한은 두지 않는다.

F-16. 재현 가능한 샘플·검증 결과

  • 동작: 오프라인 샘플, Airouter를 이용한 테스트·데모, 사용자가 설정한 실제 모델의 연결·실행 확인을 구별한다. 각 실행이 어떤 모드와 연결을 사용하는지 표시한다.
  • AC-16: 초보 사용자가 안내의 준비·입력 예시·예상 결과를 따라 핵심 흐름을 재현할 수 있다. Airouter 데모 성공을 사용자 모델 연결 성공으로 표시하지 않는다. 사용자 모델 연결과 Windows 실환경 검증이 미실행이면 그 상태를 알린다.

4. 데이터·상태·오류 기준

  • Task·Episode·Run·Session·Knowledge는 고유 식별값과 연결 관계를 가진다. 표시 이름을 바꾸더라도 다른 실행의 결과와 섞이지 않아야 한다.
  • 실행 대기·진행·완료·실패·사용자 중단·재개 가능·결과 확인 필요를 사용자가 구분할 수 있어야 한다. 세부 내부 상태명과 저장 형식은 설계에서 정한다.
  • 보존기간 설정, 저장 데이터 삭제·내보내기, 손상 이력의 수동 복구용 별도 인터페이스는 범위에서 제외한다. 기본 상태 저장·기존 기록 보존·안전한 읽기·같은 Episode의 실행 재개는 유지한다. 기능 제외를 기존 데이터 자동 삭제로 해석하지 않는다.
  • 모델 호출 실패·자료 부족·권한 거부·저장 실패·외부 결과 불확실을 서로 다른 원인으로 표시한다. 제품에 입력한 요청의 원문이나 민감정보를 오류 메시지에 그대로 출력하지 않는다.

5. 최소 품질·실행·납품 기준

  • NQ-01 안전성: 승인되지 않은 쓰기·명령 및 작업 범위 이탈이 실행되지 않는 시나리오를 검증한다. 제품의 파일·도구 권한은 실제 동작 전 검사한다.
  • NQ-02 복구성: 정상 종료·취소·강제 종료·저장 실패 뒤 상태와 데이터 보존을 확인한다. 확인되지 않은 외부 동작은 자동 재실행하지 않는다.
  • NQ-03 사용성: F-15의 터미널 조작과 오류 복구 안내를 실제 지원 환경에서 확인한다. 미측정 지연·처리량을 보장 수치로 쓰지 않는다.
  • NQ-04 재현성: 기본 기능 검증은 오프라인으로 반복할 수 있게 하고 실제 제공자 검증은 별도로 구분한다.
  • NQ-05 정보 보호: 자격증명 포함 입력·오류가 설정·이력·Knowledge·샘플·배포물에 평문으로 남는지 확인한다.
