1. 목적·사용자·제품 형태

MindCraft는 개인 사용자가 코드·문서를 분석하고 정리·생성·가공하는 작업을 터미널에서 수행하며, 이전 작업의 결과와 맥락을 다음 작업에 재사용할 수 있게 하는 도구다.

대상 사용자는 프로젝트 폴더의 자료를 다루는 개발자와 문서 작업자다. 한 사람이 작업을 이어가는 사용 방식을 우선 제안한다. 인터페이스는 CLI와 터미널 TUI, 1차 사용 환경은 Windows Terminal을 제안한다.

성공 결과는 사용자가 작업을 만들고 지정한 모델로 실행한 뒤, 결과·도구 실행·상태를 확인하고, 종료 후 같은 작업을 다시 열어 필요한 결과를 재사용하는 것이다. 단순 대화 기록 저장만으로 완료로 보지 않는다.

2. 용어와 책임 경계

  • Workspace: 사용자가 선택한 프로젝트 작업 공간. 읽기·쓰기 가능한 범위와 상태 저장 위치를 구분한다.
  • Task: 사용자가 달성하려는 작업 목적. 이름과 고유 ID를 가지며 여러 Episode를 포함한다.
  • Episode: Task 안에서 한 번의 사용자 요청을 처리하는 논리적 작업 단위.
  • Run: Episode를 수행한 개별 실행 시도. 실행 상태·선택 모델·결과·오류·재개 관계를 가진다.
  • Session: 프로그램을 시작해 종료할 때까지의 사용 구간. 여러 Session이 같은 Workspace의 기록을 순차적으로 이어갈 수 있다.
  • Knowledge: 작업 결과와 출처 정보를 함께 보존한 재사용 자료. 후보·사용 가능·거부 상태를 구분한다.
  • Model/Provider: 사용자가 지정한 모델과 호출 서비스. 제품은 설정·선택·사용자 권한·작업 상태를 관리하고, 모델 호출 기반으로 Pi 활용을 제안한다. Pi 버전과 내부 모듈 구조는 미정이다.
  • 제품의 승인 요청은 파일 변경·명령 실행 등 사용자의 실제 작업 권한을 묻는 런타임 기능이다. 작업 요청 내용 자체를 해당 권한의 포괄 승인으로 간주하지 않는다.

3. 주요 사용자 여정

  • J-01 첫 실행: 프로그램 시작 → 작업 폴더 선택 → 모델 설정 또는 오프라인 모드 선택 → 진단 결과 확인 → Task 생성 → 요청 실행 → 결과와 이력 확인. 설정이 부족하면 수정 위치와 이유를 보여주고 실행만 차단한다.
  • J-02 코드·문서 분석: Task 선택 → 허용된 자료와 Knowledge 검색 → 투입할 맥락 미리보기 → 지정 모델로 분석 → 출처와 결과 확인 → 재사용할 결과를 Knowledge로 선택.
  • J-03 문서 생성·가공: 원문과 목표 지정 → 결과 초안 확인 → 파일 변경 대상과 내용 승인 → 저장 → 실제 저장 결과와 실행 이력 확인. 거부 시 파일은 바뀌지 않는다.
  • J-04 중단 후 재개: 실행 중 취소 또는 프로그램 종료 → 재시작 후 이전 기록 확인 → 재개 가능한 실행과 결과 불확실 동작 확인 → 사용자 선택으로 새 실행 시작. 외부 동작을 무조건 반복하지 않는다.
  • J-05 재사용: 이전 결과 후보 목록 → 내용·출처 확인 → 사용 가능으로 승격 → 후속 요청에서 관련 자료 선택 → 포함·제외 사유 확인 → 결과 생성.

F-01. 작업 공간 선택·진단

  • 동작: 작업 폴더를 선택·전환하고 런타임, 상태 저장소, 모델 설정, 오프라인 실행 준비, 실제 서비스 연결 준비를 각각 진단한다.
  • 실패: 접근 불가·쓰기 불가·모델 누락·서비스 미준비를 구별하고 사용자가 조치할 위치를 안내한다. 다른 폴더로 조용히 전환하지 않는다.
  • AC-01: 모델이 없는 첫 실행에서도 설정 안내와 로컬 진단은 가능하고 모델을 사용하는 실행은 차단된다. 오프라인 진단 성공을 실제 서비스 연결 성공으로 표시하지 않는다.

F-02. Task 생성·목록·선택·상태

  • 동작: Task 이름을 입력해 생성하고, 저장된 Task 목록을 조회하며, 현재 Task를 선택한다. 완료·취소된 작업도 이력으로 확인한다.
  • 실패: 빈 이름·존재하지 않는 ID는 명확한 오류로 처리한다. Task 선택 없이 실행을 요청하면 생성·선택을 안내한다.
  • AC-02: Task 두 개를 생성하고 서로 전환했을 때 각 작업의 실행 목록과 결과가 섞이지 않는다. 프로그램을 다시 실행해도 ID와 선택 가능한 목록이 보존된다.

F-03. Episode·Run 실행과 진행 표시

  • 동작: 선택한 Task에 요청을 입력하면 Episode와 Run을 구별해 기록한다. 실행 중 응답 스트림·도구 요청·도구 결과·오류·현재 상태를 보여준다.
  • 실패: 모델 시작 실패·호출 실패·응답 완료를 구별하고, 실행 시작을 성공 완료로 표시하지 않는다. 빠른 연속 입력은 순서가 보장되거나 실행 대기임을 명시한다.
  • AC-03: 실행 전후 같은 Run ID로 요청·선택 모델·시작·완료 또는 실패를 조회할 수 있다. 실행 중에도 상태 확인과 취소 입력을 처리할 수 있다.

F-04. 명시적인 모델·용도 선택

  • 동작 제안: 모델 0개이면 실행 차단, 1개이면 모든 용도에 사용, 2개이면 서로 다른 용도에 하나씩 지정한다. 같은 용도에 중복 지정하면 실행 전에 오류를 알린다.
  • 실행 전 모델·용도·서비스와 준비 상태를 표시한다. 비용을 알 수 없으면 미확인으로 표시한다.
  • 실패: 지정한 모델을 사용할 수 없으면 이유와 수정 방법을 보여주며 다른 모델로 자동 대체하지 않는다. 실행 도중 모델을 조용히 바꾸지 않는다.
  • AC-04: 잘못된 용도 매핑은 모델 호출 전에 차단된다. 지정 서비스 실패 시 다른 서비스의 호출이 발생하지 않는다. 용도 이름과 2개 초과 지원은 Q-03에서 확인한다.

F-05. 서비스 연결과 실행 모드

  • 동작 제안: 사용자 지정 Pi 제공자, OpenAI 호환 서비스 및 로컬 제공자 연결을 지원한다. Airouter·Ollama·LM Studio·vLLM·llama.cpp를 지원 후보로 유지한다. 최종 필수 제공자 목록은 Q-04에서 확인한다.
  • 오프라인 모드는 자격증명과 네트워크 없이 정해진 시나리오로 실행한다. 실제 호출 모드와 현재 선택 모드를 명확히 표시한다.
  • 실패: 연결 실패·인증 실패·제한 초과는 원인과 재시도 가능성을 안내하고 기존 결과를 보존한다. 오프라인에서 실제 서비스로 자동 전환하지 않는다.
  • AC-05: 오프라인 시나리오 실행 시 외부 모델 호출이 0건이며 실제 서비스 성공으로 표시하지 않는다. 실행 이후 모드 변경은 기존 Run 기록을 바꾸지 않는다. 전환 경계는 Q-05에서 확인한다.

F-06. 사용자 작업 권한과 승인

  • 동작: 파일 쓰기·삭제·명령 실행·네트워크 동작은 대상과 변경·명령 내용, 필요한 범위, 실행할 Run을 사용자에게 보여주고 승인 또는 거부를 받는다.
  • 허용 작업 폴더 안의 읽기는 경로를 검증한다. 폴더 밖이나 연결 경로를 통해 범위를 벗어나는 접근은 기본 차단한다. 외부 경로의 별도 허용 가능 여부는 Q-06에서 확인한다.
  • 승인은 제시한 대상·내용·범위에만 적용한다. 대상이나 내용이 바뀌면 이전 승인으로 실행하지 않는다. 모델은 자기 요청을 스스로 승인할 수 없다.
  • AC-06: 거부한 쓰기·삭제·명령은 실행되지 않는다. 승인 전후 대상 내용을 바꿔도 기존 승인을 재사용하지 못한다. 승인 기록 저장 실패 시 동작을 시작하지 않는다.

F-07. 파일·명령 실행 결과 확인

  • 동작: 승인한 파일 변경·명령을 선택한 작업 폴더와 제한 시간 안에서 수행하고 실제 결과·오류·취소를 기록한다. 명령의 실행 파일·인자·작업 폴더를 확인할 수 있게 한다.
  • 실패: 동작 후 결과 저장이 끊겼다면 성공이나 미실행으로 단정하지 않고 결과 확인 필요로 표시한다. 결과가 불확실한 동작은 자동으로 다시 실행하지 않는다.
  • AC-07: 명령 제한 시간 초과·취소 시 관련 프로세스 정리 결과를 알 수 있다. 결과 확인 필요 상태에서 재개해도 같은 파일 변경이나 외부 동작이 자동 중복 실행되지 않는다.

F-08. 영속 이력·순차 세션

  • 동작: Task·Episode·Run·Session·모델·모드·권한 결정·도구 결과를 관계가 유지되게 저장하고 재시작 시 복원한다. 같은 작업 폴더에서 기록을 쓰는 프로세스는 하나만 허용하는 방식을 제안한다.
  • 실패: 저장 실패를 사용자에게 알리며 저장되지 않은 결과를 저장 완료로 표시하지 않는다. 기존 실행자가 살아 있으면 두 번째 기록자를 차단한다.
  • AC-08: 프로그램 종료 후 다시 시작해 작업과 실행 결과를 찾을 수 있다. 종료되지 않은 프로세스의 잠금을 해제하지 않는다. 손상 기록을 정상 기록으로 복원하지 않고 원본 보존·확인 절차를 제공한다.

F-09. 취소·종료·재개

  • 동작: 실행 취소 시 중단 상태와 당시 결과를 보존한다. 정상 종료 시 정리 결과를 남기고, 비정상 종료 후 재시작하면 미완료 Run을 식별한다.
  • 재개는 원래 Run을 덮어쓰지 않고 새 Run과 원본의 관계를 기록한다. 기존 Episode 유지 또는 새 Episode 생성은 Q-07에서 확정한다.
  • AC-09: 취소된 실행은 성공으로 보이지 않는다. 강제 종료 뒤 이전 실행·불확실 동작을 확인할 수 있고, 재개 후 원본 및 새 Run을 모두 조회할 수 있다.

F-10. Knowledge 후보·상태 관리

  • 동작: 결과 본문과 생성 Task/Run·시각·출처·자료 종류를 Knowledge 후보로 저장한다. 사용자는 목록·검색·상세에서 내용과 출처를 확인하고 승격 또는 거부한다.
  • 실패: 출처 없는 결과를 출처 검증 완료로 표시하지 않는다. 자격증명·민감정보는 재사용 자료와 화면·오류에 노출되지 않도록 처리한다.
